What the Detour generator builds

A throwaway prototype for the ticket What the generator builds. Pick a Waypoint the player is on, what is holding them back (the Target) and a seed. The page shows the Detour the generator would build: its first three Runs, each one Stage, with the Target's keys highlighted and the numbers the checks would read. Nothing here is random: the same inputs always give the same text.

What this proposes

  1. Inputs: the Waypoint (which fixes the keys allowed and the length), the Target, which Run of the Detour this is, and a seed from the Profile. Recent Stages aren't needed: a new seed already gives a new text.
  2. Run 1 is a drill; every later Run is words. A drill Stage uses the four drill shapes (repeats, alternation, anchored reach, Shift pairs). A words Stage is a list of real words, each holding a Target key. Before A and ; no word exists, so every Run is a drill.
  3. Words come from the Word list, the commonest first, and a word with more Target keys is more likely. A Mix-up prefers words holding both of its keys.
  4. Made-up words only where real ones run out (fewer than 15): in practice only at A and ; and the Home row review. They are made and vetted ahead of time, so nothing is checked in the browser.
  5. Digits and symbols ride on words in the shape they have in real text: (word), $47, word-word, Word?. Never sentences or prose.
  6. The same inputs and seed give the same Stage in every browser: integer-only random numbers, and the generator's version and Word list version are part of the Stage's source.

Highlighted characters are the Target's keys. "Fingerprint" is a short code of the text: equal codes mean identical text.
